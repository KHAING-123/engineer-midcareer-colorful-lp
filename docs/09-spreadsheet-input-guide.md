# Google Spreadsheet 入力ガイド(14項目の文章)

## 1. このガイドの目的
Colorful LP の見出し・説明文(7 Section の `title`・`lead`、計14項目)を、Google Spreadsheet で入力するための入力表の使い方をまとめる。入力表の雛形は `docs/templates/colorful-text-input.csv`。

## 2. 現在の状態(最初にお読みください)
- `generate-colorful-lp` Skill は、**Markdown(`.md`)に加えて、この CSV(`.csv`)を指定できる**ようになった(Skill に CSV 入力の手順とスクリプトを追加済み)。
- CSV の読み取り・検証はスクリプト(`.claude/skills/generate-colorful-lp/scripts/`)で行う。
- **CSV からの LP 生成は、1件変更のテストを1回、実施済み**：Skill 経由で、検証・複製・反映・`npm ci`・Build・起動まで成功し、ユーザーの画面確認(CSV の見出し反映、PC、SP 390px・375px、Opening・メニュー・ナビ)も OK だった。詳細は `docs/10-csv-generation-test-result.md`。
- ただし、確認したのは**1件変更(`jobsSection.title` のみ)の1回だけ**。複数件の変更、エラー時の Skill 経由の停止、実際の案件の文章での確認などは未実施(「10.」を参照)。
- スクリプトの単体テストと、Skill 経由の実行結果は、別のものとして区別している(「10.」を参照)。
- 対象は**14項目の文章だけ**。次は未対応。
  - 画像の差し替え
  - カード(仕事・ステップ・サポート・キャリア・面接トピック・選考ステップ)の内容
  - リンク・URL
  - 色、番号、英字ラベル、補足メッセージ
  - デザインの選択(他の Design Pattern を含む)

## 3. CSV の内容
列：`項目ID,セクション,項目名,操作,入力内容,備考`

| 列 | 内容 | 編集 |
|---|---|---|
| 項目ID | `lpContent.js` の実際のキー(例：`membersSection.title`) | **しない** |
| セクション | `01 MEMBERS` など | **しない** |
| 項目名 | `見出し`(title)または `説明文`(lead) | **しない** |
| 操作 | `維持` または `変更`(初期値は `維持`) | **する** |
| 入力内容 | 現在の `lpContent.js` の値。`変更` のときに反映される内容 | **する** |
| 備考 | 改行が「強制」か「候補」かの説明 | しない |

- 14行(7 Section × 見出し・説明文)。項目IDは重複しない。
- 入力内容の改行は、セル内改行(セルの中の改行)で保持している。空行(`\n\n`)も保持している。
- 文字コードは UTF-8(BOM なし)。

### 14項目の一覧
| 項目ID | セクション | 項目名 | 改行 |
|---|---|---|---|
| membersSection.title | 01 MEMBERS | 見出し | 候補 |
| membersSection.lead | 01 MEMBERS | 説明文 | 強制 |
| jobsSection.title | 02 OUR WORK | 見出し | 強制 |
| jobsSection.lead | 02 OUR WORK | 説明文 | 強制 |
| growthSection.title | 03 GROWTH STEP | 見出し | 強制 |
| growthSection.lead | 03 GROWTH STEP | 説明文 | 強制 |
| supportSection.title | 04 SUPPORT | 見出し | 強制 |
| supportSection.lead | 04 SUPPORT | 説明文 | 強制 |
| careersSection.title | 05 CAREER PATH | 見出し | 強制 |
| careersSection.lead | 05 CAREER PATH | 説明文 | 強制 |
| interview.title | 06 INTERVIEW | 見出し | 強制 |
| interview.lead | 06 INTERVIEW | 説明文 | 強制 |
| selectionSection.title | 07 FLOW | 見出し | 強制 |
| selectionSection.lead | 07 FLOW | 説明文 | 強制 |

### 改行の「強制」と「候補」
- **強制**：セル内の改行が、画面でも必ず改行になる。入力した位置で改行される。
- **候補**：改行位置は「幅が足りないときだけ折り返す位置」になる。`membersSection.title` だけが該当する。
- 画面での見え方(折り返し・はみ出し)は、ブラウザで確認が必要(未確認)。

## 4. 操作の使い方
| 操作 | 動作(設計) |
|---|---|
| 維持 | 現在の値を使う。入力内容は読み込まない(編集しても反映されない)。 |
| 変更 | 入力内容を反映する。 |

- 変えたい項目だけ、操作を `変更` にして、入力内容を書き換える。
- 変えない項目は、`維持` のままにする。入力内容も触らない。
- **`変更` で入力内容が空、または空白・改行だけの場合はエラー**とする。削除とはみなさない。項目を消したい場合は、別途相談する(現在は対応しない)。
- 操作は `維持`・`変更` の2つだけ。ほかの値はエラーとする。
- 入力内容の中の行頭・行末の空白は、削らずそのまま使う想定。意図しない空白を入れない。

## 5. Google Sheets へ取り込む手順
1. Google Drive を開き、「新規」→「Google スプレッドシート」で空のスプレッドシートを作る。
2. 「ファイル」→「インポート」→「アップロード」で、`docs/templates/colorful-text-input.csv` を選ぶ。
   - Codespaces のファイルは、事前にエクスプローラーの右クリック「ダウンロード」でローカルに保存しておく。
3. インポートの設定：
   - インポートの場所：「スプレッドシートを置換する」(空のシートの場合)
   - 区切り文字の種類：「カンマ」(自動検出でも可)
   - 「テキストを数値、日付、数式に変換する」：**オフ**
4. 「データをインポート」を押す。1行目が見出し、2〜15行目が14項目になっていることを確認する。
5. セル内改行が保持されていることを、「入力内容」の列のセルで確認する(必要に応じて行の高さを広げる)。

### 取り込み後の推奨設定(任意)
- 操作の列(D2:D15)：「データ」→「データの入力規則」→「プルダウン」で `維持`・`変更` の2つを設定する。
- 入力内容の列に、`変更` かつ空白だけの行を赤く表示する条件付き書式を設定する。カスタム数式の例：`=AND($D2="変更",LEN(TRIM($E2))=0)`
- 項目ID・セクション・項目名の列は、「保護されたシートと範囲」で編集を制限しておくと安全。

## 6. 入力のしかた
- 編集するのは**「操作」と「入力内容」の2列だけ**。項目ID・セクション・項目名・備考は変更しない(項目IDが変わると、どの項目か分からなくなる)。
- 行の追加・削除・並べ替えはしない。14行のままにする。
- セルの中で改行するには、Google Sheets では `Ctrl + Enter`(Mac は `Command + Enter`)を使う。
- 説明文の途中の空行は、そのまま空行として維持される。
- 画像内の文字(Hero・Members・最終CTA)は、この表では変えられない。

## 7. CSV を書き出して Codespaces へ置く流れ
1. 入力が終わったら、「ファイル」→「ダウンロード」→「カンマ区切りの値(.csv)」で書き出す。
   - 書き出されるのは、現在開いているシートだけ。
2. ダウンロードしたファイルを、Codespaces のリポジトリ内に置く(エクスプローラーへドラッグ＆ドロップ、またはアップロード)。
   - 置き場所の例：`docs/templates/` とは別の、案件用のフォルダ。雛形(`colorful-text-input.csv`)は上書きしない。
3. 置いたあと、次を確認する。
   - 14行そろっていること(項目IDの重複・欠落がない)。
   - セル内改行が保持されていること。
   - 文字化けがないこと(UTF-8)。
4. 「8. CSV 入力の実行方法」の手順で実行する。

## 8. CSV 入力の実行方法
Claude Code で、Input に CSV、出力先に `output/` 直下の新しいフォルダを指定する。

```
/generate-colorful-lp docs/tests/colorful-text-input-test.csv output/colorful-csv-test
```

- 拡張子が `.csv` なら CSV 入力、`.md` なら従来の Markdown 入力として扱う。Markdown 入力の手順は変えていない。
- Skill は、まず CSV をスクリプトで検証する。**検証に成功した場合だけ**、複製・反映・`npm ci`・Build・起動へ進む。失敗した場合は、出力フォルダを作らずに停止し、エラーを報告する。
- 反映するのは、`操作` が `変更` で、入力内容が現在値と異なる項目の `title`・`lead` の1行だけ。ほかの行・ファイルは変更しない。

### スクリプトを単体で実行する(LP は生成しない)
```
node .claude/skills/generate-colorful-lp/scripts/read-csv-input.mjs <CSVファイル> [--out <JSONの保存先>]
```
- 結果は JSON で標準出力に出る。終了コード 0＝検証成功、1＝検証エラー、2＝使い方の誤り。
- JSON の主な項目：`ok`、`errors`(エラー)、`warnings`(警告)、`counts`(維持・変更の件数)、`changes`(項目ID・変更前・変更後)、`file`(BOM・末尾改行・CRLF の有無)。
- 反映用の `apply-changes.mjs` は、Skill が複製後に使う(単体で `frontend/` には書き込めない)。

## 9. 検証ルール(スクリプトが判定する)
CSV の文字列は**データとして扱い、コードとして実行しない**。文章の前後の空白・改行は削除しない。

| 区分 | ルール | 違反したとき |
|---|---|---|
| 文字コード | UTF-8。先頭の BOM は有っても無くてもよい。 | エラー |
| 改行 | 行末は LF・CRLF のどちらも可。末尾の改行は無くてもよい。セル内の CRLF は LF に正規化する。単独の CR はエラー。 | エラー(単独の CR) |
| 引用符 | 引用符内のカンマ・`""`(二重引用符)・セル内改行を正しく読む。閉じていない引用符、引用符なしセル内の `"`、閉じ引用符の直後の不正な文字はエラー。 | エラー |
| ヘッダー | `項目ID,セクション,項目名,操作,入力内容,備考` の6列。 | エラー |
| 件数・列数 | データが14件、各行が6列。空行はエラー。 | エラー |
| 項目ID | 14項目が重複・欠落・不明なくそろっている。行の並び順には依存せず、項目IDで対応させる。 | エラー |
| 操作 | `維持` または `変更` だけ。前後に空白があってもエラー。 | エラー |
| `維持` | 生成時の frontend の現在値を使う。入力内容を編集していても反映しない。 | 警告(入力内容が現在値と違う場合) |
| `変更` | 入力内容をそのまま使う(前後の空白・改行も保持)。現在値と完全に同じなら、書き換えない。 | — |
| `変更` で空 | 空文字・空白だけ・改行だけ(全角空白・タブを含む)はエラー。出力フォルダを作る前に停止する。 | エラー |
| セクション・項目名 | 想定と異なる場合は警告。反映には使わない。 | 警告 |

## 10. 確認済みの範囲と未実施の範囲
### A. 確認済み:スクリプトの単体テスト(一時領域。LP は生成していない)
- 実際の Google Sheets 書き出し CSV(`docs/tests/colorful-text-input-test.csv`。ヘッダー・末尾改行なし・CRLF 行末)で、「変更1件・維持13件」になり、変更は `jobsSection.title` の「【CSV検証用】PREAIでの仕事」だけであること。
- 雛形 CSV(`docs/templates/colorful-text-input.csv`)で、変更0件になること。
- BOM あり、CRLF、末尾改行なし、行の逆順でも読めること。
- カンマ・二重引用符・セル内改行・前後の空白を含む値を、そのまま保持できること。
- 次を検知して、エラーにできること：閉じていない引用符、引用符なしセル内の `"`、閉じ引用符の直後の不正な文字、単独の CR、不正な UTF-8、空ファイル、ヘッダーの不一致、行数・列数の不一致、空行、項目IDの重複・欠落・不明、操作の不正(`維持`・`変更` 以外、前後空白つき、空)、`変更` で空・空白(半角・全角・タブ)・改行だけ。
- `維持` は入力内容が違っても現在値を使い、`変更` でも現在値と同じなら書き換え対象にしないこと。
- 反映スクリプトを、一時領域にコピーした lpContent.js に実行し、変更した1行だけが置き換わり、読み込み直した値が期待どおりであること。`'`・`\`・改行・U+2028/2029・コード風の文字列を含む値でも、コードとして実行されずに保持されること。
- frontend 自身や、複製と異なる書き込み先、変更前の値が違う計画、空白の変更後の値は、拒否して書き込まないこと。
- 一時領域のテストは、Input・雛形・frontend・既存出力を変更していない。

### B. 確認済み:Skill 経由の CSV 生成(1件変更を1回。`docs/10-csv-generation-test-result.md`)
- 実行：`/generate-colorful-lp docs/tests/colorful-text-input-test.csv output/colorful-csv-test`(Google Sheets から書き出した CSV。変更1件・維持13件)。
- CSV の検証成功(エラー・警告0件)。変更は `jobsSection.title` の「PREAIでの仕事」→「【CSV検証用】PREAIでの仕事」だけで、反映後の差分も指定のキーと値に一致した。
- `npm ci` 1回で成功(esbuild の postinstall に関する npm の警告あり。CSV 検証の警告とは別)、Build 成功(2.37秒)、開発サーバー 5175 で HTTP 200。資料読込込みの合計 47秒(うち読込 12秒。ブラウザ確認の時間は含まない)。
- `frontend/` と既存の出力は変更なし。
- ユーザーの画面確認：CSV の見出し反映、PC、SP 390px、SP 375px、Opening・メニュー・ナビ(すべて OK)。

### 未実施

- Google Sheets 上でのプルダウン・条件付き書式・保護の設定(推奨設定の動作)。
- 実際の案件の文章での確認。
- Skill に書いた停止(検証エラー時に出力フォルダを作らない)を、Skill 経由で実行した確認。スクリプトのエラー検知は確認済みだが、Skill の手順に従って AI が停止するかは未確認(機械的な強制ではなく、Skill の指示による停止)。
