# Input 不備・対応範囲外の変更による停止動作の検証結果

## 1. 目的と範囲
- `generate-colorful-lp` Skill が、入力不備と対応範囲外の変更を検出して、生成前に停止するかを確認した。
- 確認したのは2ケース。ほかの不正 Input(空白だけ・見出しだけで値がない・単独の CR・閉じ忘れ・重複など)は、実行テスト未実施。
- 元の `frontend/`、既存Input(docs/01〜03・06)、既存出力、Skill、ZIP、`docs/archive/` は変更していない。Commit・Push はしていない。

## 2. 実施方法
- テスト用 Input は `docs/02-customer-input.md` を基に、`docs/tests/` へ新規作成した(既存ファイルの上書きなし)。どちらも712行で、`docs/02` との差分は指定した1行だけ。
- Skill はユーザーが `/generate-colorful-lp` で実行した。
  - 経緯: Skill は `disable-model-invocation: true` のため、AI が Skill ツールで呼び出すことはできない(エラーで拒否された)。手順を別の方法で再現せず、ユーザーに実行を依頼した。
- 各実行で、Skill の手順(0 開始時刻 → 1 引数検証 → 2 資料の全文読込 → 3 作業前の記録 → 4 照合)に従った。
- 読み込んだ行数(各ケース共通): 01=69、02=712、03=58、06=384、SKILL.md=276、指定Input=712、lpContent.js=423。
- 期待結果に合わせた結果の作り上げはしていない。想定外に生成へ進んだ場合は、そこで停止して報告する方針だった(該当なし)。

## 3. テスト1：空文字
- Input：docs/tests/empty-title.md
- 出力先：output/test-reject-empty-title
- 入力差分(`docs/02` との diff)：185行のみ。`jobsSection.title` の値「PREAIでの仕事」を空行にした。「### 見出し」とコードブロックの囲みは残した。
- 期待結果：判断不能として、生成前に停止する。
- 実際の結果：**期待どおり停止した**。
  - 14項目の分類：13項目が「同じ」、`jobsSection.title` が「判断不能」。変更・未指定は0件。
  - 停止理由：手順4-1の「空」(コードブロックの中身が空、または改行だけ)。削除とみなさず、意図(削除か記入漏れか)が分からないため確認が必要として停止。
  - 停止した手順：手順4-1(照合)。範囲外の差分の照合(4-3)は、停止後のため行っていない。
- 出力先の有無：**なし**。
- 複製・Input反映・`npm ci`・Build・サーバー起動：いずれも実行していない(ポート一覧も実行前後で同じ)。
- 時間：資料読込完了まで8秒、照合完了まで10秒。
- 元データ：`frontend/`、既存の `output/`、docs、`docs/tests/`、`docs/archive/`、ZIP、Git 状態は作業前後で同じ。

## 6. 未確認事項と注意
- Skill は AI が手順を読んで実行する指示書であり、プログラムとして機械的に強制されるものではない。今回は2回とも、手順どおりに停止することを確認した。実行者や状況が変わっても毎回同じになるかは、この2回の結果だけでは保証できない。
- 次の不正 Input による停止動作は、実行テスト未実施。
  - 見出しだけあり、値(コードブロック)が無い
  - 空白・タブ・全角スペースだけの値、「見出し：」の後ろが空の1行書式
  - 単独の CR、CRLF の扱い
  - コードブロックの閉じ忘れ、同じ項目の重複
  - 空白だけの差
  - 範囲外の差分のうち、`jobs[0].description` 以外(番号・ラベル・タグ・URL・画像パス・色・補足メッセージなど)
  - 出力先が既に存在する、`output/` 外・`..` を含む出力先など、手順1の引数検証
- 今回は停止動作の確認のため、画面表示(ブラウザ)の確認は対象外。
- 判定の補助に、これまでの検証と同じ読み取りスクリプトを使った。範囲外の差分(テスト2)は、`jobs[0]` の説明だけをスクリプトで確認し、他の範囲外データはテスト用 Input が `docs/02` と1行しか違わないこと(diff)に基づいて差分なしとした。
